이 문서 하나가 이전 핸드오프 3건(Claude 세션 핸드오프 2026-10-14, ChatGPT 검토 핸드오프, `my-constraints.md`)을 대체한다. 규칙의 정본은 여전히 레포 `docs/ref5-program-spec.md`(main)이고, 이 문서는 현재 상태·결정·열린 항목을 한곳에 모은 요약이다. 스펙과 이 문서가 다르면 스펙이 맞다.

`docs/ref5-v1.4-oap-proposal.md`·`ref5-v1.4-implementation-plan.md`는 비규범 기록이다. `ref5-program-spec-v1.3*`, `hybrid-*`, `async_protocol_*`은 폐기본이라 근거로 쓰지 않는다.

## 2. 현재 상태 (DB, 10/14 세션 반영)

플랜 `REF5 Adaptive Strength 프로그램 2`(엔진 514), 9/05 시작, 14세션. 구 플랜 `REF5 Adaptive Strength 프로그램`은 7/19–9/01 15세션.

| 항목 | 값 |
|---|---|
| SQ H3 / H2 / V | 85 / 90 / 75, 현 창 하드 3/6 |
| BP 집중 / 볼륨 | 85 / 70, 현 창 2/4 |
| PULL 집중 총중량 | 90(잠금 +15), 현 창 2/4 |
| DL / OHP | 75 / 32.5(OHP는 BP 90 전까지 상한으로 동결) |
| OAP | 좌 1단 PASS 2/3, 우 2단 0/3 |
| 다음 집중 | PULL |

지금까지 주종목 창은 전부 INCREASE, 주종목 HOLD·FAIL은 없다. 다만 현재 기준은 REF5 이전 TB 시절 무게(SQ 92.5×3, BP 90×3, PULL 약 94 총중량)보다 낮아서, 이 전승은 아직 프로그램 효과의 증거가 아니다.

## 3. 목표와 제약 (REF5 기준으로 갱신)

목표는 그대로다. G1 체중 약 70 kg에서 하이바 SQ 175 kg(2.5×BW, 다년, KPI = SQ e1RM÷체중), G2 SQ 1순위, G3 하이바가 목표 동작, G4 다년 수용, G6 원암 친업(상체 1순위·전체 2순위, 2026-09 추가). 체중은 75 kg에서 주 0.25%로 70 kg 근처까지 천천히 내리고, 벌크는 하지 않는다.

제약 C1–C11도 그대로다. 불규칙 일정(C1), 회복 부족(C2), 클라이밍 월 1–2회(C3), 주 2–4회(C4), 다섯 종목만·보조 금지(C5, v1.4부터 OAP 슬롯만 예외), SQ 우선(C6), DL ≤ SQ(C7), OHP ≤ BP×0.5(C8), 1RM 측정 거부(C9), RIR 거부(C10), 대회 아님·꾸준한 증량(C11).

`my-constraints.md`에서 REF5와 맞지 않는 항목은 다음과 같다. "TM = 1RM×0.87", "AMRAP + e1RM 추세", "AMRAP만 RPE 9까지"는 Hybrid v0.5 시절 내용이다. REF5에는 TM·AMRAP·RPE 목표가 없고, "세션 RPE 7–8"도 스펙 규칙이 아니다. "바 느려지면 컷"은 스펙 §11.1(첫 명백한 감속 반복까지 세고 종료)로 이어진다. K4 "헤비 세션만 로우바"는 폐기됐다. 하드 SQ도 하이바로 하고 있어 스펙(§3.2, 하이바만)과 일치한다(2026-10-16 사용자 확인).

무릎(대퇴사두건 부착부 통증, 미진단)은 프로그램 밖 개인 운영이다. 2026-10-16 사용자 보고로는 매우 좋아졌다. 깊이·자세 통제와 워밍업 등척성 익스텐션으로 관리하고, 벤치에서는 플랫 풋으로 레그드라이브를 교정했다. 2–3주 관리에도 일상 통증이 정체·악화하면 전문가 확인이 필요하다.

## 4. 확정 결정

판정 기준(FAIL 0·HOLD ≤1·볼륨 veto)은 완화하지 않는다. 획득률이 낮으면 첫 해석은 자극·회복 부족이다(§21.1). 예정 디로드는 두지 않는다. 근거(Coleman 2024)는 이 선택과 모순되지 않지만 지지하는 것도 아니다. 중량딥스는 추가하지 않고, 마무리 딥스·마무리 OAP는 v1.4 컷오버 때 없앴다(OAP는 슬롯으로 흡수). 1RM 시도는 하지 않는다(중량풀업 마지막 싱글은 110 = 75+35). 강등을 피하려는 그라인딩은 금지다. 감속이 보이면 컷하고 판정을 받아들인다. 스펙 변경은 §26 형식으로 한 번에 한 요소만 한다.

## 5. 열린 항목

1. **체중 입력.** 세션 체중은 입력하지 않아 기본값 75.00이 들어가지만, 실제 체중도 변화가 없다(2026-10-16 사용자 확인). 스펙 §20도 첫 평가 게이트까지 체중 유지라 지금은 PULL 잠금·총중량이 대체로 맞다. 감량을 시작하면 그날부터 실측 입력이 필요하다. 엔진은 창 시작 때 `목표 총중량 − 계산 체중`으로 추가중량을 잠그므로(§10.1), 실제 72 kg인데 75가 남아 있으면 추가중량이 3 kg 덜 처방되고 기록 총중량은 3 kg 부풀려진다. 주 3회 이상 입력하면 7일 평균이 계산 체중이 된다.
2. **평가 권고 중 미착수 항목.** 판정 밖 기록(수면·클라이밍·통증·무릎 유발검사·스탠스 변화), 시작 패널에 168시간 창이 열리는 시각 표시(UI, v1.5 [#761](https://github.com/dawntide/workout-log/pull/761) 머지로 불필요해짐), §21.1 사전 등록 보강(예전 최고 무게를 넘기 전 INCREASE는 효과 증거로 세지 않음), 플랜 전환 전 상태 수기 기록 규율.
3. **알려진 구조적 비용.** OHP 동결(§22.4 #5), DL이 SQ 상한에 묶여 창이 버려지는 문제, PULL 볼륨 veto 사실상 미발동(§22.4 #10), 168시간 경계가 주 1회 같은 요일 루틴과 분 단위로 겹치는 문제(v1.5 [#761](https://github.com/dawntide/workout-log/pull/761)이 달력 7일로 바꿔 해소), 플랜 전환 시 창·정체 이력 초기화.
4. **팔꿈치 장부.** 헤비 풀업 + OAP + 클라이밍. 되돌리기 권장 조건은 팔꿈치 통증 2주 이상 또는 PULL 집중창 2연속 유지다.
5. **인프라(훈련 외).** prod DB RLS가 전 테이블에서 꺼져 있다. 미해결이다.

## 6. 이전 핸드오프 의심점 처리 결과

ChatGPT 핸드오프의 A–F는 2026-10-14에 최신 코드와 대조해 정리했다. A(OAP 좌1→좌2→우1→우2 순서·150초 타이머)는 UI 갭이고 판정과는 무관하다. 지금 타이머는 120초다. B(48시간 분리)는 스펙 문구 오류였고 PR #760에서 정정했다. C(2주 체류)는 밀도 규칙상 최소 14일이라 이미 충족되고, 문구만 PR #760에서 정리했다. D·E·F는 스펙이 알고 받아들인 비용이다(§22.4 #9–#11, 프리 쿨다운 START 기준은 의도된 동작). 제안 P2(OAP를 BP 앞으로)와 P3(SQ V 4×5)는 근거 부족으로 보류한다.
