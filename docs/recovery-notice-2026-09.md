# 운동 초안 복구 안내 개선 — 2026-09-14

홈에 기기의 오래된 초안 전체가 "미저장 운동"으로 노출되어 저장 실패 기록처럼 보였다. 목록은 localStorage와 IndexedDB만 읽었고 서버 기록과 대조하지 않았다.

## 운영 점검 (읽기 전용)

Supabase `workout-log-prod`의 `public` 스키마를 READ ONLY 트랜잭션으로 조회했다. 사용자가 제공한 iPhone 화면에는 2026-07-18 REF5, 07-17 및 07-08 Tactical Barbell 초안이 있었다.

- 실제 계정의 07-17 Tactical Barbell 기록은 11세트가 저장되어 있다.
- 07-08과 07-18에는 해당 계정의 저장 기록이 없다. 인접한 07-09 Tactical Barbell 및 07-19 REF5 기록은 존재하나, 같은 초안이라고 단정할 수 없다. UTC/한국 날짜를 모두 확인했으며 날짜 차이는 단순 시간대 변환으로 설명되지 않는다.
- 화면의 옛 REF5 플랜은 보관 상태이고, 현재 활성 플랜은 이름에 `2`가 붙은 별도 플랜이다.
- 실제 계정의 저장 기록은 78건. 최근 7일 수집된 이벤트에는 저장 성공 2건, 저장 실패 0건이 있었다. 생성 세션별 중복 기록 그룹은 0건이다. 수집되지 않은 실패까지 없다는 의미는 아니다.
- 기기 초안의 원문은 서버에 없으므로 사진만으로 저장 기록과 입력 내용이 완전히 같은지는 확인할 수 없다. 운영 데이터는 수정하거나 삭제하지 않았다.

## 동작 변경

- 오늘 운동 영역 다음에 작은 초안 안내와 `목록 보기` / `나중에`를 표시한다. 목록은 바텀 시트로 연다.
- 넘긴 안내는 동일한 초안 목록에 대해 재방문/새로고침 시에도 접힌 상태를 유지한다. 작은 복구 목록 버튼으로 다시 열 수 있으며, 초안이 추가/갱신되면 다시 알린다.
- 서버 조회는 초안이 있을 때만 수행한다. 로그 ID, 생성 세션 ID 또는 클라이언트 저장 식별자로 해당 사용자의 기록만 확인한다. 날짜나 프로그램 이름만 같다고 같은 운동으로 간주하지 않는다.
- 식별자와 실제 기록 내용이 같은 복사본은 안내에서 제외한다. 변경된 횟수·중량·메모·RPE·세트 타입·날짜·REF5 결과 및 미완성 입력은 보존한다. 서버 조회 실패 시에도 로컬 초안을 유지한다. 자동 삭제하지 않는다.
- 목록에서 불필요한 초안을 명시적으로 삭제할 수 있다. 확인 단계를 거치며, 서버 운동 기록은 지우지 않는다.

## 검증 및 배포 범위

순수 비교 테스트, 390px 모바일 E2E(안내 접기/재표시/목록/삭제/서버 복사본 제외/네트워크 실패/계정 소유권), 기존 다음 날 복구 여정을 검증한다. 새 E2E는 CI의 실제 로그인 레인에도 포함한다. 실제 iPhone 저장소 원문 검증은 포함하지 않는다.

스키마/마이그레이션/환경변수 변경 없음. 회귀 시 이전 웹 배포로 되돌릴 수 있고, 숨긴 초안은 로컬에 보존되어 있다.
