### 2026-10-14

**(1) 프로그램 사실의 기준은 저장소 최신 코드와 `docs/ref5-program-spec.md`다. Claude·ChatGPT 핸드오프 문서는 과거 이력일 뿐 정본이 아니다.**
이유: 이유 미기록(사용자 지시). 후속 검증에서 핸드오프에 스펙 사실 오류가 실제로 있었다(§7.3 48시간 보장 문구 등, 10/16 #760). 대안: 핸드오프 문서를 정본으로 — 버린 이유 미기록.

**(2) 운동 종목은 SQ·가중 풀업·BP·DL·OHP 5개뿐, 보조운동 없음. SQ가 최우선, 상체는 OAP 우선. DL ≤ SQ TM, OHP ≤ BP×0.5. 1RM 테스트·RIR 미사용. 무릎은 프로그램 범위 밖.**
이유: 사용자 제약 C1–C11(불규칙 일정, 회복 부족, 클라이밍 월 1–2회 등)에서 나옴. 개별 이유 미기록. v1.4부터 OAP 슬롯만 보조 금지의 예외. 대안: 중량딥스·마무리 딥스·마무리 OAP·1RM 시도 — 중량딥스는 추가하지 않았고 마무리 딥스·OAP는 v1.4 컷오버 때 없앴다(OAP는 슬롯으로 흡수). 이유 미기록.

**(3) 판정 기준(FAIL 0, HOLD ≤ 1, 볼륨 veto)은 완화하지 않는다. 예정된 디로드는 두지 않는다.**
이유: 사용자 방침. 획득률이 낮으면 첫 해석은 자극·회복 부족이다(스펙 §21.1). 디로드 부재는 Coleman 2024가 모순되지 않지만 지지하지도 않는다. 판정을 느슨하게 만드는 우회(예: 피로를 `EXTERNAL`로 분류)도 같은 이유로 막는다 — (19) 참조. 대안: 예정 디로드 — 근거 부족으로 도입 안 함(세부 이유 미기록).

**(4) 스펙 변경은 §26 변경관리 형식으로, 한 번에 한 요소만 바꾼다.**
이유: 이유 미기록(사용자 지시). 흐름: docs PR(스펙 선행) → 구현 PR.

**(5) 휴식 타이머는 REF5 엔진이 스트림별로 처방하며 사용자 설정보다 우선한다. 값은 스펙 범위의 최소값 — 집중(SQ H3/H2·BP·PULL) 180초, 볼륨·OHP·마이크로·OAP 120초, DL 120초 (#757).**
이유: 사용자가 스레드 "PWA 알림 적용 검토"에서 선택. 처방이 정본이어야 한다는 것 외의 세부 이유 미기록. 대안: 스펙 범위의 다른 값(상한 등) — 버린 이유 미기록.

### 2026-10-18 ~ 2026-10-20

**(19) 2026-10-18 SQ H2 기록을 `EXTERNAL`로 분류한 것을 폐기하고 2026-10-20에 `CLEAR_SLOWDOWN`(FAIL)으로 정정했다.**
이유: 스펙 §11.1–§11.3상 피로·그라인딩은 `EXTERNAL`(장비·시간·환경)이 아니다. `EXTERNAL`로 두면 판정 완화 금지 방침(3)을 조용히 어긴다. 사용자는 처음에 `EXTERNAL`을 유지하려 했으나 설득되어 가드된 SQL을 직접 실행했다. 결과: SQ 창 4/6(INCREASE 불가), SQ_H2 failStreak 1(다음 H2 FAIL이면 −2.5), 다음 hard H3 85.
대안: `EXTERNAL` 유지(창 3/6 올-PASS, 다음 hard H2 90) — 위 이유로 버림. 정식 밸브는 시작 시점 MICRO 선택(§8-1).

**(8) 운동 기록 수정은 앱 UI(로그 열기 → 운동 카드 "종료 사유" → 저장) 또는 사용자가 직접 실행하는 가드된 SQL로만 한다. 에이전트의 Supabase 직접 쓰기는 하지 않는다. (2026-10-20)**
이유: 스레드의 직접 prod 쓰기가 세션 안전 검사에서 차단됐다. 앱 저장은 전 세트 재정규화 + `rebuildRef5ProgressionForPlan`으로 `plan_runtime_state`·통계 캐시를 한 트랜잭션에서 갱신하지만, 원시 SQL은 `meta.ref5.terminationReason`과 모든 세트의 `completionFingerprint`를 함께 고쳐야 하고 캐시 상태가 다음 시작까지 낡는다.
대안: 스레드에서 직접 SQL 쓰기 — 차단됨, 버림(20).

**(9) PULL↔OAP 사이 간격 규칙(48시간 분리)을 추가하지 않는다. (2026-10-20)**
이유: 결과가 자가조절된다 — OAP 7회 중 3회가 PULL 집중 약 24시간 뒤였으나 PULL 집중은 항상 PASS였다. 팔꿈치 부하는 사용자가 관리(불편하면 SAFETY, 2주 초과 통증이면 revert).
대안과 버린 이유: ① §26 48시간 분리 규칙 — 48시간 이내 HOLD/FAIL이 재발할 때까지 보류. ② 하루치 피로에 revert 사용 — PULL 볼륨 veto 위험이 있어 금지, 대신 micro. 참고: 스펙 §7.3의 "구조적으로 보장" 문구는 틀려서 #760에서 정정.

### 2026-10-22

**(10) 볼륨은 현행 유지한다. 윈도우가 정체되면 §23.1 순서(회복 점검 → 볼륨 점검 → 볼륨 슬롯 +1세트를 §26 후보로)를 적용한다.**
이유: SQ는 Pelland 2026 무릎(주 약 5세트)을 이미 넘었고, heavy BP/PULL(주 약 3세트)은 최소 유효량 하한이다. 닫힌 SQ/BP/PULL 창은 전부 INCREASE였고 첫 주종목 FAIL(10/18)은 연속일 뒤라 현재 한계는 자극보다 회복으로 보인다(추정). 현재 중량이 6월 3×3보다 낮아 기록으로는 볼륨 충분 여부를 아직 검증할 수 없다. 비대는 ACSM 2026 기준(≥10세트/근육/주)에 못 미친다(외삽, 논쟁 중).
대안: 볼륨 +1세트 — 먼저 종목별 정의가 필요해 지금은 보류(첫 의심 대상은 SQ가 아니라 BP/PULL).

대안과 버린 이유: 26.04 대응(Playwright 업그레이드·덤프 호환) — 사용자가 고정을 선택(세부 이유 미기록).
