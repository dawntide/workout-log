# 인증·저장·복구 보강 — 2026-09-13

이번 변경은 인수 분석에서 발견한 인증과 데이터 보존 문제를 대상으로 한다. 운영 배포·운영 DB 변경은 하지 않았다.

## 반영한 동작

- Google이 검증한 이메일이라는 이유만으로 기존 비밀번호 계정에 자동 연결하지 않는다. 기존 계정으로 로그인한 뒤 설정 > 계정에서 명시적으로 연결해야 한다. 시작과 콜백 양쪽에서 실제 세션을 확인한다. 이미 연결된 Google 로그인은 유지한다.
- 일반 운동의 신규 초안에 `clientMutationId`를 생성하고 직렬화·복구·저장 요청까지 유지한다. 요청 직전에 초안을 동기 저장한다. 서버 커밋 후 응답만 유실돼도 동일 입력 재시도는 기존 기록을 반환한다. 입력을 바꾼 재시도는 서버의 기존 충돌 정책을 따른다.
- 복구 시트를 닫는 동작과 삭제를 구분한다. 닫기/나중에 복구는 초안을 보존하고 홈으로 이동한다. 보류한 초안을 빈 편집기로 덮어쓰지 않도록 자동 저장을 막는다. 6시간 만료를 제거하고 홈에 미저장 운동 진입점을 추가한다.
- 플랜 없는 기존 기록에도 초안 키를 부여한다. 비동기 초안 저장이 삭제 뒤 다시 살아나는 경쟁을 줄이고, 삭제 시 localStorage를 먼저 지운다.
- Bearer API 요청을 Hono의 실제 인증·스코프 검사까지 전달한다. 웹 전용 인증 API와 페이지는 기존 세션 검사를 유지한다.
- 캐시 무효화 전에 시작한 읽기 결과는 캐시/화면에 되돌려주지 않는다. 새 읽기는 이전 요청과 분리한다. IDB 웜업도 무효화 세대를 확인한다.
- JSON v1 백업에 선택적 `progressionDecisions`를 추가한다. 새 파일은 파일의 선택을 기준으로 재계산한다. 구 파일은 기존 DB의 같은 로그 선택을 보존하되 한계를 경고한다. 외부 로그 참조·중복·잘못된 선택은 삭제 전에 거부한다.
- 정기 DB 백업에 `drizzle` 스키마를 포함하고 마이그레이션 이력 누락을 검사한다. CI에 백업 복원 후 마이그레이션 재실행을 추가한다.
- 저장 클릭·실패·성공 이벤트에 재시도 식별자를, 성공 이벤트에 기록 ID를 추가한다.

## 확인한 결과

별도로 생성한 loopback PostgreSQL 클러스터와 테스트 계정만 사용했다.

- core 유닛 711개, 웹 앱 유닛 249개 및 웹 스크립트 가드 통과.
- 실제 DB 통합 테스트 4개 통과: 무단 Google 연결 거부, 명시적 연결과 재로그인, 신규 Google 계정, 원본 삭제 후 JSON만으로 사용자 증감량 선택 복원.
- Chromium 개발 서버 E2E 11개 통과: PAT 수명 주기 8개, 일반 초안 새로고침, 복구 보류/24시간 후 홈에서 복구, 서버 저장 응답 유실 후 새로고침과 중복 없는 재시도.
- 기존 public-only 백업은 복원 후 마이그레이션에서 `module_target already exists`로 실패. public+drizzle 백업은 새 DB 복원과 마이그레이션 재실행 통과.
- web/core/apps-api 타입 검사, 웹 lint·디자인 lint, core no-any 검사, API 경계 검사, diff 공백 검사, Next 프로덕션 빌드 통과.
- core 경계 스크립트는 Windows 셸의 `!` 비호환으로 직접 실행되지 않아 동일 금지 import 패턴을 `rg`로 검사했다. 위반 없음.
- 프로덕션 실행 모드 E2E는 자동 승인 검토가 로컬 `next start` 실행을 차단해 미실행. 상세 사유는 제공되지 않았다. GitHub CI 실행 결과도 아직 확인하지 않았다.

## 남은 범위

- 실제 Google 제공자 왕복 로그인, 실제 iPhone/Safari/PWA 검증.
- 이미 연결된 계정에 대한 과거 무단 연결 여부 조사와 세션 정리는 이번 변경에 포함하지 않는다.
- 공용 프로그램 정의까지 포함한 독립적인 JSON 이식, REF5 전용 복원, 과거 로그 재계산 시 파라미터 스냅샷 보존은 별도 작업이다. 새 JSON도 이 전체 문제를 해결했다고 보지 않는다.
- 프로토콜이 맞지 않는 REF5 초안의 기존 호환성 처리 정책은 유지한다. 이번 보존 개선은 호환되는 초안의 닫기·시간 만료·발견 경로를 다룬다.
- 기존 백업 파일은 수정되지 않는다. 변경된 정기 백업은 해당 워크플로가 반영된 뒤 생성되는 파일에 적용된다.
- 피로도 모델, 휴식 타이머, 배포 파이프라인 단일화와 다른 제품 제안은 이번 변경 범위 밖이다.

## 후속 보강

- 과거 날짜의 신규 기록이나 순서를 바꾸는 수정으로 전체 진행 재계산이 필요할 때, 현재 저장에서 전달한 사용자 선택이 우선 적용되도록 연결했다. 선택을 새로 보내지 않은 날짜 수정은 기존 선택을 보존한다.
- REF5 백업 가져오기는 일반 진행 리듀서 대신 REF5 전용 재생을 사용한다. 시작만 한 세션과 완료된 세션 모두 가져오기 트랜잭션 안에서 진행 상태·시작/완료 이력·세션 상태를 복원한다. 손상된 스냅샷의 재생이 실패하면 가져오기 전체가 롤백된다.
- 로컬 PostgreSQL 통합 테스트는 위 경우를 포함해 7개 통과했다. 파일 위치는 `web/integration/reliability.test.ts`이며 CI가 `integration/*.test.ts`를 발견해 실행한다.
- 과거 파라미터 스냅샷, 공용 프로그램 정의의 독립적 이식, iPhone 실기기 검증은 계속 남아 있다.
